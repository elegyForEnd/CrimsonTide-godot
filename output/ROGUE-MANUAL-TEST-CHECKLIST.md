### I-02 · 服务房 ESC 第一次离店、第二次才弹暂停菜单 **（已更新）**
- **前置**：站在锻炉/赌徒/镜像房里，面板在屏幕上。
- **步骤**：按一次 ESC；再按一次 ESC。
- **预期**：**第一次** ESC → 等同点「离开此间」（`room_left=true`、面板收起），**不弹**暂停菜单（`main.gd:1528-1534`：`_rogue_panel_open_revision>=0` 且 `_rogue_leave_attempted != 该值` 才走离店）。**第二次** ESC → 弹「守夜通讯」暂停菜单（`main.gd:1535-1536`）。若服务端拒了第一次离店（例如还有队友挂着待发三选一），第二次 ESC 会自动落到暂停菜单而不是被永久吞掉（`main.gd:117-120` 的设计意图）。**注意 R7e 起这个开关与 I-01 的面板显示门共用同一个函数 `RogueRoomUi.panel_open()`**（`main.gd:3655-3663` 的注释就是在讲这件事），所以不会再出现「一边以为面板在、另一边以为不在」的缝。
- **不符先查**：`main.gd:1526-1537`（ESC 分派）、`main.gd:3655-3663`（`_rogue_panel_open_revision` 每 tick 刷新）、`rogue_room_ui.gd:49-75`（`room_left` / `panel_open`）、`rl:1268`（接受的两个相位）。

### I-05 · 默认 HUD 树里的「离开商店」不再是幽灵按钮（新增）
- **前置**：局内任意时刻。
- **步骤**：①在一场**战斗**中（或任何非商店相位、非商店房）看屏幕上方标题行区域，找有没有一个几乎看不见、但能点的「离开商店」；②走进**游商房**（`raid.room=="shop"`，含点完「离开商店」后的 `rogue_exit`）再看同一位置。
- **预期（已修）**：**战斗中、以及任何不在游商房的相位里，都不应出现可点的「离开商店」**。这个按钮以前没有登记进默认树的 `_rogue_hud_nodes`，而默认树的显隐循环只处理 `[i,"part"]` 形状的结构 key，字符串 key 一律不管 → 它在**任何**相位（含战斗）都保持 `visible`，点下去被相位门拒掉（无害），但暗场景里留下一个字体色透明、几乎看不见却能点的按钮。现在它已登记为 `"leave_shop"` 并按**值级**写 `visible`，条件是：
  `session.raid.room=="shop" and session.raid.phase in ["rogue_shop","rogue_exit"]`（`main.gd:4188-4190` 登记、`main.gd:4217-4223` 刷新）。**「在商店房」这一条是关键**：只按相位判定会让按钮在"别处走到 `rogue_exit`"时也冒出来（`exit_hint` 那句通用指路行覆盖的面更宽，两者刻意不再逐字相同）。
- **不符先查**：`main.gd:4181-4190`（登记与注释）、`main.gd:4201-4223`（值级显隐与 `room=="shop"` 条件，注释里写了上一版为什么是错的）、`main.gd:4199-4200`（对照用的 `exit_hint`）。**注意：这段代码在本清单复核期间仍在被修改，行号可能已前后漂移 ±20 行，定位时请用「`leave_shop` / `leave_shop_open` / 幽灵按钮」这些字串搜索。**
- **优先级**：P1

# 十一、T2 · 面板增量刷新（**本批风险最高**）

> 原理：`rogue_panel` 现在是**常驻控件树**，只有「面板种类」或「结构类字段」变化才重建（`main.gd:77-113`、`:3670-3700`）。数值类改动走值级刷新。风险在于「某个本该重建的结构变化没进指纹」→ 按钮指向旧下标/旧 revision → 表现为**点了没反应**或**点错行**。

# 十三、已知的预期行为（**不是 bug**，请勿误报）

1. **CU08「迷雾」只降级成 HUD 一行文字**：`vision` 在魔境渲染侧没有接入点（世界绘制只有平移，没有缩放/遮罩层），所以画面**不会真的变暗**，只在右栏诅咒区多一行「· 视野 -35%（迷雾压低了目视距离）」。见 `rogue_ui_model.gd:77-87` 的显式说明。
2. **服务位随机到「铭刻」时该行禁用**：因为铭刻需要「再指定行囊里的一件武器」这个二级选择，而 300×47 的货架按钮放不下；按钮写「铭刻 · 暂不可购买」，tooltip 指向行囊构筑页（35 魔晶）。其余 7 种服务都能买。见 `main.gd:3936-3945`、`rl:1109-1116`。
3. **派生链预览只出现在「构筑」页签，并会盖住构筑页正文左侧约 468px**：这是刻意的取舍——面板根节点 `mouse_filter=IGNORE`，**下面的按钮照旧可点**；面板里唯一吃鼠标的是那个 60×26 的「关闭 ×」（`rogue_build_preview.gd:102-105,117-123`）。挪走它会压到右下角 HUD 提示。**在「物品」页签完全看不到它是正确行为**（见 U-01b）。
4. **点「离开商店」离店不可逆**：离店后相位变 `rogue_exit`，商店面板不会再回来（同一个按钮再点会被房态门拒掉）。这是设计：游商被刻意排除在「ESC 离店」之外，ESC 只弹暂停菜单（`main.gd:3691-3694`、`rl:1233-1252`）。
5. **付费刷新的按钮可用性只在面板重建时刷新**：`paid_reroll_check()` 在**建树时**问一次、把结果挂到 `disabled` 与 tooltip 上（`rogue_reward_ui.gd:210-223`）。因此「刚花完钱导致魔晶不足」「刚捡到钱」时，按钮文字/禁用态可能滞后到下一次面板重建（换卡、换屏、切面板）。**按下去也不会出问题**：服务端会回一条明确的中文原因（`rl:800-805`）。
5b. **服务房面板在开箱 / 领完奖励后仍然留着，这是设计（R7e）**：`finish_rewards()` 会把相位推到 `rogue_exit`，但那**不等于**玩家想离店，所以三个专属房的面板继续显示、服务行继续可点；面板只在「点离开此间 / 按 ESC」这类**主动**离店后才收起（`rogue_room_ui.gd:56-75`、`main.gd:3743-3756`）。同样地，**走到下一间房**面板自然消失（`rl:339` 进房即清 `room_left`）。如果面板在主动离店后仍留在屏幕上，那才是 bug（查 I-01 的「不符先查」）。
6. **商店货架不参与掉落保底**：保底只作用于开箱（`LOOT_PITY_CHEST`），商店走无保底分支（`rl:557-563,891-894`）。保底计数器**每层清零**（`rl:168-175`）。
7. **赎罪只能清「最近获得的那一条」**：不是自选诅咒（`rogue_curses.gd:177-189`）。价格随层递增 165 / 210 / 255 / 300 / 345，**始终高于任何一条诅咒当场给的魔晶**（最高 150），这是刻意的反白嫖设计（`rogue_rooms.gd:43-52`）。
8. **回收价可能低到 8 魔晶**：低价位（白装、低层）回收收益很小，且回收价永远低于同品质买价（`rl:979-992`）。
9. **`rogue_sold`（不可重复回收的台账）是玩家字典的一部分**，会随快照同步；正常玩法几乎遇不到「卖同一件两次」，它主要是防旧包重放（`rl:1021-1026`）。
10. **疾行长靴可能被移速天花板吃掉一部分**：`speed` 被夹在「英雄基础速度 + 70」（`session.gd:2706`），叠加装备/属性后可能触顶，所以高等级长靴的边际提升会不明显。这是既有公式，不是本次改动引入。

# 十四、回归风险最高的地方（为什么值得重点看）

1. **T2 面板增量刷新（第一风险）**：`update_rogue_hud()` 从「签名一变就整棵重建」改成「常驻树 + 分域脏刷新」（`main.gd:77-113,3631-3700`）。任何**结构类变化没进 `layout` 指纹**，都会让复用的按钮指向过期下标或过期 `revision` → 症状正是用户最敏感的「**点了没反应**」。重点走 T2-01 / T2-02 / T2-03 / T2-07 / T2-08：四种面板各进出 3 次、面板内连点、买卖后回收区行序、三选一版本推进。
2. **铭刻修复（第二风险）**：以前铭刻按钮**从来没生效过**（多传实参被默认值静默吞掉），现在真的会扣 35 魔晶并改 `rogue_id`（`rogue_build_ui.gd:135-147`、`main.gd:3850-3857`、`rogue_build.gd:865-868`）。它牵动 24 枚符文的被动效果、武器命名、以及 Q/R/T 新键位，所以要用 U-04 单独确认「刻上、扣钱、可换、有 ✓」。
3. **A1 成长树接线后的数值平衡**：11 个原本的死节点现在全部落地（`session.gd:480-503`）。其中三个是**乘法**且叠在既有的 rubber-band 之外（`enemy_hp` / `enemy_damage`，`rogue_build.gd:943-955`），两个是**长期全局乘数**（`gold`、`xp_gain`，`rl:520-522`、`rogue_build.gd:1036-1057`）。逐级上限很小（-4%/级等）且都被 `BOUNDS` 夹住（`rogue_growth.gd:137-153`），但**满级叠加**（例如满级屠戮研习 + 铁躯 + 守望重甲）会明显改变难度曲线——建议重点看 G-02 里这三条的实际手感，而不是只看「有没有生效」。
4. **诅咒同池相加的边界**：`move_speed` / `shop_price` / `chest_drop` / `heal_scale` 是变数、诅咒、成长树**三源相加**（`session.gd:484-488`），各自有 `CAPS`（`rogue_curses.gd:26-36`）与成长 `BOUNDS`。极端组合（深袋满级 -20% 遇上 CU04 +35%）可能出现「折扣被诅咒吃掉」，看到的是叠加结果而不是单一来源，别当成 bug。
5. **服务房 / 商店的相位门（R7e 后已改为「主动离店」门）**：`rogue_leave` 是这次新加的出口，它同时给商店补上了两行区域结算（`cleared+1` 与 `Build.award`，`rl:1246-1252`）；服务房那一侧则改成"只在主动离店时收起面板"（`room_left`，`rogue_room_ui.gd:39-75`），并且该动作现在在 `rogue_reward` **与** `rogue_exit` 两个相位都被接受（`rl:1268`）。若这里出错，症状是「离店后面板还在」或「开箱后点服务行没反应」或「本区奖励少发一次」。用 T2-10 / I-01 / I-02 / I-03 加 F-01 交叉验证最有效。
6. **默认树的「值级显隐」新约定（幽灵按钮修复）**：控件始终存在、只改 `visible`，所以相位**不进** `_rogue_hud_layout` 指纹（`main.gd:4184-4186`）。风险在于「新加的控件忘了登记 `_rogue_hud_nodes` 字符串 key」——那会让它像这次的「离开商店」一样在**所有**相位常驻。新增默认树控件时请顺手核对 `main.gd:4180-4189` 的登记与 `:4200-4209` 的刷新。
