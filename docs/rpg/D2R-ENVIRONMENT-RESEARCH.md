# 连续区域与3D地编研究、重做记录

2026-10-10。检查对象为用户指定的 `F:\game\Diablo II 1.13C原版懒人包` 和 `F:\game\D2R`。两处目录只读，未启动安装器、修改原包或使用原游戏美术制作本项目。

## 本地检查范围

旧包补读 `Levels.txt`、`LvlWarp.txt`、营地、过渡口、桥、墓地及上下层DS1模板。得到137个关卡表记录（含Null占位）、89个出口表记录、7个详细地图样本。完整表与样本见 [reference-region-inspection.json](reference-region-inspection.json)。之前的地块、子格碰撞与MPQ研究保留在 [MAP-IMPLEMENTATION-RESEARCH.md](MAP-IMPLEMENTATION-RESEARCH.md)。

重制包的 `.build.info` 显示版本 `1.2.69270`，对应本地构建配置标记为 `2.4.1.2 RC 5 / build 69270`；这是所检查的本地构建，不代表最新发行版本。28个 `data.*` 文件合计30,002,519,549字节。资源不是散装FBX文件，而在CASC容器中。

这份安装的ENCODING键没有出现在本地IDX中，通用读取库未能正常打开。研究工具改为只读本地IDX、验证BLTE分块MD5、解压Z/N分块、解析TVFS目录和文件跨度。成功枚举170,703个目录条目，包含2,276个DS1、263个DT1、58,735个 `.model` 名称和30,874个 `.texture` 名称。名称包括LOD与变体，不能理解为同等数量的独立场景。

HD环境preset目录有2,099个JSON条目，包括地图模块、道具样板和仓库。详细解析23个样本，包括第一幕营地与过渡、三向桥、墓地、墓穴上下层、第二幕城市与下水道上下层、第三幕码头与桥、第四幕桥。每个样本记录SHA256、模型依赖数量、组件计数、局部变换高度与组件样本，见 [d2r-scene-inspection.json](d2r-scene-inspection.json)。原始JSON仅保存在忽略的研究输出目录中。

## 地图如何组织

旧版的区域并不是一张无限大小地图。营地、野外区域、地城层级各有自己的关卡定义；野外连接让玩家沿地面继续走，门洞、洞口、上下楼梯把玩家送到另一层或另一地区。需要区分连续的野外连接和副本入口。

`Levels` 中的 `DrlgType` 区分预制、迷宫、野外等生成方式；`Vis0..7` 与 `Warp0..7` 描述入口目的地与出口表现。第一片野外记录80×80的大小，四个洞口朝向槽位指向同一洞穴关卡8，而下一个野外关卡有自己的洞穴目的地。这说明洞穴是野外上的可发现分支，不是“走到底后自动进入下一条相同走廊”。野外相邻关系并非全靠TXT的Vis列表达，不能仅据这张表声称还原了原版完整生成器。

`Waypoint` 是关卡功能配置，不应在进入任意地区时自动赠送快速旅行。在玩家的地图中，亲自发现并激活传送点才有意义：它把漫长探索路途变成可回访的路线，而不是取代探索本身。

## 重制版如何摆场景

场景JSON含 `dependencies`、`entities`、`terrain`、`biomeFilename`、`perTileBiomeOverrides`、`specialTiles` 等项。JSON记录的是层级实体、依赖和变换；实体再引用网格、材质、粒子和物理资源，不能把JSON当成完整模型。

抽样中的第一幕东向营地有1,639个entities、254个 `WallTransparencyComponent`；南向桥样本有162个entities。第三幕码头样本有4,989个entities。数字包含装饰与效果，不都是可交互物体。与上一版每张图放几棵树、几栋房子的做法相比，场景细节密度和功能分工差距很大。

| 本地实际组件 | 读到的内容 | 本项目应如何使用这个原则 |
|---|---|---|
| TransformDefinitionComponent | position、四元数orientation、scale、继承选项 | 先统一单位和坐标，再摆地形、建筑、碰撞；不能显示脚下高台、人物却仍站零高度 |
| ModelDefinitionComponent | 模型路径、visibleLayers、lightMask、shadowMask、floorModel、terrainBlendMode | 地面、墙、屋顶、前景植被拆开处理，避免一整个房子永远挡住角色 |
| TerrainStampDefinitionComponent | 遮罩、R/G/B层索引、biome、stomp与snap | 草、泥、路、河岸需要有边缘过渡，避免一条硬边贴图穿过整张图 |
| ModelVariationDefinitionComponent | 候选资源与变体 | 同一地编语言可以复用模块，但应改变组合、破损、尺度和朝向 |
| PhysicsBody / PhysicsFixture / PhysicsBox | 单独的物理定义 | 显示网格和可行走区域有关联；屋檐可遮挡，但不能把整个建筑外包围盒当作不可进入区 |
| WallTransparencyComponent | drawOrder、wallTileLocalCoord | 固定相机下处理墙体与角色遮挡；不是让角色永久穿透所有3D物体 |
| AudioEmitter、Vfx、SpotLight | 环境声、粒子和局部灯光 | 室外日月光、室内提灯与火炬、遗迹入口各有自己的气氛 |

参考模型依赖常用无LOD基础名称，而归档里存有 `_lod0..4.model` 等具体文件；纹理也包含 `_alb`、`_nrm`、`_orm` 等材质通道。这些命名提供资源组织证据，不代表本次已经解码了完整网格、重建了闭源材质或复现原游戏渲染器。

重制版依然保留原游戏逻辑，叠加现代3D表现，这是[官方发行说明](https://investor.activision.com/news-releases/news-release-details/gates-hell-are-open-diablor-ii-resurrectedtm-now-live)明确说明的。开发者的[码头场景作品说明](https://rachelrelyea.com/projects/qemkgn)也描述了按原布局与正交相机制作场景blockout、处理材质与一致性的流程。辅助核对使用[HD/DS1编辑器源码与文档](https://github.com/D2R-Reimagined/reimagined-level-editor)及[CascLib源码](https://github.com/ladislav-zezula/CascLib)；它们是独立工具，不能冒充原游戏引擎源码。

## 本次落实的重做

每幕现在组织为一片连续地表，包含营地、相连野外区域和通向副本的入口。每个野外模块从旧版2400×3000扩大到4800×4800；连接方向有南北主线和东西分支。跨越地区时保留角色坐标、相机、伙伴与当前交战状态，地表不反复拆除重建。各幕地城结构包含长厅、十字礼拜堂、回廊书库、矿洞、墓室等；相邻地下层通过楼梯继续深入，并能返回原入口。每幕首片野外另设一处两层的可选洞窟，共增加12个探索层，独立宝箱与守卫，不强制代替主线任务。

`story_region.gd` 定义实际空间，`story_map.gd` 组织区域图和寻路，`story_environment.gd` 生成连续地面与模块建筑。道路距离写入顶点权重，地表材质在草、土与路之间混合；河面具有微弱波纹，河岸增加石块与边缘；野外细小地形起伏与楼梯、台地使用同一高度查询。人物仍是2D精灵，但脚底、任务物、投影与相机均采样地形高度。

房屋有可行走室内和门洞；进入屋内隐藏屋顶与前墙，离开恢复。固定正交相机保留3D深度遮挡，遮住操作角色的附近前景树/墙会被临时隐藏。营地加入不同地标：要塞塔楼、白垩拱廊、矿业驿站、篱园、码头、王城断墙。仍使用项目现有授权资产和程序网格，并未导入参考游戏美术。

传送阵按E激活，只连接已激活地点；M离开阵时显示探索地图。在支路与高台发现宝箱，奖励一次；探索记录持久化。伙伴和敌人使用可行走网格绕墙寻路。NPC、传送点、宝箱、任务对象与副本上下层通路均作连通性检查。

## 验收与仍需精制的部分

测试涵盖全六幕的区域图、NPC、任务锚点、宝箱、地下层与寻路；渲染测试检查高差站立、屋顶隐藏和恢复、地图面板，并截取各幕营地、野外、桥、矿洞、墓室、书库和女王场地。测试数量与最新可玩范围见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。

这次建立了连续探索、分层副本与3D地编系统，但目前美术仍包含程序建筑和现有风格化资产。没有达到重制版的写实材质、逐关手工雕刻、千级细节布置、全部天气效果或完整照明品质。相邻地区敌人只在所在地区参与模拟；地表网格预构建后按邻近区域显示，尚非按磁盘流式加载。楼梯是可行走高差与层间入口，暂未实现同一平面上两条可重叠通行的多层桥道。

没有声称进入参考游戏逐关试玩、反编译其全部引擎或把其资源完整移植。本地报告记录了真实读取范围，代码与截图记录本项目实际做出的效果。
